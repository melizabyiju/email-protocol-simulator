📊 Comprehensive Protocol Comparison Matrix

Comparison of the core Application Layer protocols used in Internet electronic mail according to RFC standards:

Feature / Parameter SMTP (RFC 5321) POP3 (RFC 1939) IMAP (RFC 3501)
Primary Role Push: Message submission and inter-server transfer Pull: Mail access / retrieval to local client Pull & Sync: Remote mailbox access & management
Default Ports Port 25 (relay), 587 (submission), 465 (SMTPS) Port 110 (plaintext), 995 (POP3S over TLS) Port 143 (plaintext), 993 (IMAPS over TLS)
Transport Protocol TCP (Reliable connection-oriented stream) TCP (Reliable connection-oriented stream) TCP (Reliable connection-oriented stream)
Server Copy Retention N/A (Forwarding agent & queue) Typically deleted after download (unless configured to keep) Persisted indefinitely on server; synchronized across all devices
Multi-Device Support N/A Poor (downloaded mail exists only on that single machine) Excellent (all devices view identical folders and read status)
Folder Organization None Single flat inbox on client Full hierarchical folders (Inbox, Sent, Drafts, Trash) on server
Message Flags None None (only retrieved or not) Rich state flags (\Seen, \Answered, \Flagged, \Deleted)
Partial Message Download No (entire message submitted) No (downloads full message with all attachments) Yes (can fetch headers only, or stream specific MIME parts)
Resource Consumption Transient spool memory Low server disk usage; high client storage Higher server storage and memory required

🎭 Complete 5-Member Role-Play Presentation Script

Role Play Overview: A synchronized classroom presentation where each team member represents one stage of the email architecture, demonstrating protocol commands and answering viva questions.

Member 1: Sender / User Agent (UA)

"Good morning respected teacher and friends. I am representing Member 1, the Sender and User Agent. Whenever someone composes an email, the User Agent provides the user interface, structures the email into standard RFC 5322 headers (From, To, Subject, Date), and handles non-text attachments using MIME encoding. Because email is a store-and-forward system, I do not send the email directly to Bob's laptop; instead, I push it to my outgoing SMTP submission server using TCP port 587."

Member 2: Sender's SMTP Server (Outgoing MTA)

"I am Member 2, representing the Outgoing SMTP Server. SMTP is the Simple Mail Transfer Protocol (RFC 5321). When Alice's client connects, I execute a greeting and authenticate her credentials. Once accepted via the DATA command, I store the message in my local Spool Queue. I then consult DNS for the MX (Mail Exchange) record of 'example.org' to determine which server is responsible for receiving Bob's email, preparing it for transmission."

Member 3: Internet & Network Layer

"I am Member 3, representing the Internet Backbone and Routers. While SMTP is an application layer protocol, it relies entirely on TCP/IP underneath. I establish a reliable TCP 3-way handshake over port 25 between the two servers. My routers fragment and forward the IP packets hop-by-hop across autonomous systems, ensuring end-to-end delivery across the physical and logical internet."

Member 4: Recipient Mail Server (Incoming MTA & Mailbox)

"I am Member 4, the Recipient Mail Server. My incoming SMTP listener receives the message, validates that 'bob.receiver' is a real user in my domain, performs spam/malware checks, and deposits the email safely into Bob's server mailbox storage (/var/mail/bob). Because Bob's device might be turned off or offline, my server safely preserves the email until he requests it."

Member 5: Receiver Client (POP3 vs IMAP Access)

"I am Member 5, representing Bob and the Mail Access protocols. Because SMTP is strictly a push protocol, a recipient cannot use SMTP to pull mail from their mailbox. Instead, we use either POP3 or IMAP. In POP3 (RFC 1939), the client downloads the message to local storage and typically issues a DELE command to remove it from the server. In IMAP (RFC 3501), the message stays on the server, allowing multiple devices like phones and laptops to stay synchronized with read/unread flags. Today we demonstrate both branches on the exact same stored message!"
